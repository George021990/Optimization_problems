# Оптимизационная модель календарного планирования флота

Модель строит календарный график работы флота на горизонте планирования и максимизирует суммарную прибыль.

## Решаемая задача

Для каждого судна и каждого дня нужно определить:

- состояние: промысел, переход, порт (отгрузка / стоянка / ремонт), перегрузка;
- местоположение (зона промысла, порт или маршрут);
- объём груза в трюме, вылов, выгрузку и передачу продукции.

Соблюдаются технологические и ресурсные ограничения: квоты, вместимость трюма, окна промысла, длительность переходов, максимальная продолжительность рейса, заранее заданный график ремонта, логика встречи процессора и транспортника.

Типы судов:

| Тип | Обозначение | Роль |
| --- | --- | --- |
| `LIVE_CRAB_CARRIER` | V1 | ловит и сам доставляет живого краба в порт |
| `PROCESSOR` | V2 | ловит, перерабатывает, передаёт продукцию транспортнику |
| `TRANSPORT` | V3 | принимает продукцию у процессора и везёт её в порт |

## Алгоритм

Задача формализована как **смешанно-целочисленная линейная модель (MILP)** и решается ветвями и границами (solver CBC из PuLP).

### Переменные

- бинарные местоположения и режимы: `loc`, `start`, `in_tr`, `fish`, `transfer`, `repair`, `idle`, `unload_bin`, `meet`;
- непрерывные потоки: вылов `x`, выпуск `y`, трюм `H`, выгрузка в порту `U`, перегрузка процессор→транспортник `Q`.

### Ограничения (по документу)

1. **Вылов и квоты.** Суммарный вылов вида краба не выше квоты и не ниже минимума освоения; суточный вылов не выше производительности судна в зоне; промысел только в допустимом окне и только в режиме «промысел».
2. **Трюм.** Баланс загрузки:
   - V1: остаток + вылов − выгрузка в порту;
   - V2: остаток + выпуск продукции − передача транспортнику;
   - V3: остаток + приём от процессора − выгрузка в порту.
   Вместимость не превышается.
3. **Перегрузка V2–V3.** Передача возможна только при совместном нахождении в одной зоне в один день, оба судна в режиме перегрузки; в этот день процессор не ведёт промысел.
4. **Движение.** Переход стартует только из фактической локации по допустимой дуге; в пути судно находится `τ_{ij}` дней и прибывает в пункт назначения; каждый день судно либо в точке, либо в переходе.
5. **Порт.** В порту ровно один подрежим: ремонт, стоянка или отгрузка. Для транспортника стоянка запрещена.
6. **Ремонт (входные данные).** График ремонта задаётся заранее окнами `(судно, порт, день начала, длительность)`. В эти дни судно обязано находиться в указанном порту в статусе «Ремонт»: промысел, переход и перегрузка запрещены. Вне графика статус ремонта не назначается.
7. **Рейс.** В любом скользящем окне длины `voyage_limit` судно хотя бы раз заходит в порт.

### Целевая функция

Максимум прибыли:

`Прибыль = Доход − Операционные − Транспортные − Портовые − Экипаж`

- доход — цена × выгрузка в порту;
- операционные — постоянные суточные, выпуск, тара;
- транспортные — топливо на промысле и на переходе;
- портовые — заход, стоянка, ремонт;
- экипаж — оклад плюс процент от дохода.

На выходе формируется календарный график (раздел 13 документа): судно, день, статус, локация/маршрут, вылов, загрузка трюма.

## Тестовые данные

Встроенный экземпляр (`optimization_north/data.py`):

- горизонт 8 суток;
- порт «Петропавловск», зоны «Зона-Запад» и «Зона-Восток»;
- три судна: краболов V1, процессор V2, транспортник V3;
- один вид краба, две продукции (живой и варёно-мороженый);
- время перехода между любыми точками — 1 сутки;
- квота 180 т;
- входной график ремонта: V1 в Петропавловске дни 7–8, V2 в Петропавловске день 8.

Набор достаточен, чтобы одновременно отработать промысел V1 с самостоятельной доставкой и связку процессор–транспортник.

## Установка и запуск

Требуется Python 3.9+.

```bash
python -m pip install -r requirements.txt
python -m optimization_north.main
```

Полезные аргументы:

```bash
python -m optimization_north.main --time-limit 60 --output schedule.csv --quiet
```

| Аргумент | Смысл |
| --- | --- |
| `--time-limit` | лимит времени CBC в секундах (по умолчанию 30) |
| `--output` | путь к CSV с календарным графиком |
| `--quiet` | не печатать лог решателя |

После расчёта в консоль выводятся статус, разложение прибыли и таблица графика. CSV по умолчанию пишется в `optimization_north/schedule.csv`.
